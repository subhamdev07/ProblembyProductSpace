## 1. Architectural Principles & Boundaries

The P0.5 architecture establishes clean, decoupling boundaries between primary document acquisition, optical character recognition, and downstream language modeling.

```
+-----------------------------------------------------------------------------+
|                          WORKSPACE ARCHITECTURE                             |
|                                                                             |
|   +-----------------------+              +------------------------------+   |
|   |  P0 Syllabus Layer    |              |   P0.5 AI Infrastructure     |   |
|   |  - 5 CBSE Units       |              |   - Centralized NVIDIA LLM   |   |
|   |  - 13 NCERT Chapters  |              |   - Bodhan Indic-OCR         |   |
|   |  - 48 Topics          |              |   - Hybrid Document Pipeline |   |
|   |  - SQLite Storage     |              |   - Security & Secret Masking|   |
|   +-----------▲-----------+              +--------------▲---------------+   |
|               │                                         │                   |
|               └────────────────────┬────────────────────┘                   |
|                                    │                                        |
|                     +--------------▼---------------+                        |
|                     |   Future Phases (P1 - P6)    |                        |
|                     |   - Concept Graph (P1)       |                        |
|                     |   - Diagnostic Engine (P2)   |                        |
|                     |   - Learner Model (P3)       |                        |
|                     +------------------------------+                        |
+-----------------------------------------------------------------------------+
```

### Core Design Invariants:
1. **Strict Service Separation:** 
   - Bodhan Indic-OCR is dedicated exclusively to image-to-text transformation.
   - NVIDIA Nemotron is dedicated exclusively to natural language processing and structured educational synthesis.
   - Bodhan never calls NVIDIA; NVIDIA never calls Bodhan.
2. **Centralized Client Access:** Application components are strictly forbidden from instantiating their own `openai.OpenAI` or `requests` clients for AI calls. All requests route through `NVIDIANemotronService` or `BodhanOCRService`.
3. **Reasoning Content Privacy:** Nemotron reasoning tokens (`reasoning_content`) are stored internally in `LLMResponse` for developer audits and are **never exposed to end-user students or frontend interfaces**.
4. **Source Traceability Preservation:** Ingested documents retain page numbers, source IDs, character counts, and extraction methods (`NATIVE_TEXT` vs `BODHAN_OCR`) to link downstream concepts back to primary textbook pages.

## 3. Configuration & Security Topology

Configuration is strictly environment-driven via `src/core/config.py`:

```
                       [.env / Environment Variables]
                                     │
                                     ▼
                       [AIInfrastructureConfig]
                       ├── NVIDIAConfig (provider, model, base_url, api_key, etc.)
                       └── BodhanOCRConfig (provider, base_url, api_key, dpi, etc.)
                                     │
                                     ▼
                        [Security & Sanitization]
                        ├── mask_secret() -> Redacts key in diagnostics
                        ├── sanitize_headers() -> Masks Authorization headers
                        └── sanitize_log_message() -> Redacts tokens via regex
```

### Fail-Safe Initialization Guarantee:
The entire backend system starts safely without credentials. If an operation is requested without credentials, a typed `LLMConfigurationError` or `OCRConfigurationError` is raised with instructions on how to set the environment variable, preventing unhandled crashes.

## 5. Extensibility & Future Phase Enablement

- **P1 (Concept Graph Engine):** Will consume validated text from `DocumentExtractionResult` and use `NVIDIANemotronService` with `json_mode=True` to extract atomic concept nodes and prerequisite edges.
- **P2 (Diagnostic Assessment):** Will leverage `NVIDIANemotronService` to formulate assessment items aligned with Bloom taxonomy verbs and Curricular Goals.
- **P3 (Learner Model):** Will update student belief distributions without direct coupling to either OCR or LLM infrastructure.
