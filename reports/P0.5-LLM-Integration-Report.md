## 1. Executive Summary

As part of the P0.5 AI Infrastructure phase, the **NVIDIA Nemotron 3.5 Lightning 30B A3B** model has been integrated into a centralized, resilient, and secure service architecture. The service interfaces with NVIDIA's OpenAI-compatible Chat Completions endpoint (`https://integrate.api.nvidia.com/v1/chat/completions`) using the official Python `openai` SDK (v2.41.1).

### Key Architectural Highlights:
- **Centralized Service Enforcement:** Application modules never instantiate ad-hoc LLM clients. All LLM calls pass through `NVIDIANemotronService` in `src/ai/llm_service.py`.
- **Reasoning Content Isolation:** Thinking tokens produced by Nemotron (`reasoning_content`) are strictly isolated in `LLMResponse.reasoning_content`. Internal chain-of-thought is preserved for backend diagnostics and quality analysis but is **never exposed to student or frontend responses**.
- **Dual Mode Support:** Both synchronous non-streaming (`generate`) and real-time streaming (`stream_generate`) are supported with full typing.
- **Fail-Safe Startup:** The system initializes without crashing if `NVIDIA_API_KEY` is omitted, returning explicit `LLMConfigurationError` exceptions when generation is requested.
- **Zero API Credential Exposure:** Secrets are masked in logs and reports using `mask_secret` and regex-based redaction patterns.

## 3. Client Implementation & Request Lifecycle

The centralized service is implemented in `src/ai/llm_service.py`:

```
Input Messages (List[Dict[str, str]])
               │
               ▼
   [NVIDIANemotronService]
   ├── 1. Configuration Check (is_configured?)
   ├── 2. Lazy OpenAI Client Init (timeout=120s, max_retries=0 handled in app)
   ├── 3. Extra Body Assembly (chat_template_kwargs: enable_thinking=True, reasoning_budget=16384)
   ├── 4. Request Dispatch to https://integrate.api.nvidia.com/v1
   ├── 5. Retry Loop on Transient 429/Timeout/5xx Errors (up to 2 retries)
   ├── 6. Response Validation & Reasoning/Content Separation
   └── 7. Latency (ms) & Token Usage Aggregation
               │
               ▼
          LLMResponse
          ├── content: str (user-facing)
          ├── reasoning_content: Optional[str] (internal only)
          ├── model: str
          ├── usage: Dict[str, int]
          └── latency_ms: float
```

## 4. Streaming Implementation

The streaming generator `stream_generate()` yields tagged tuples `(chunk_type, text)`:
- `("reasoning", delta.reasoning_content)`: Internal chain-of-thought tokens.
- `("content", delta.content)`: Final student-facing answer tokens.

```python
for chunk in stream:
    if not chunk.choices:
        continue
    delta = chunk.choices[0].delta
    
    # 1. Reasoning chunk
    reasoning = getattr(delta, "reasoning_content", None)
    if reasoning:
        yield ("reasoning", reasoning)
        
    # 2. User-facing content chunk
    if delta.content:
        yield ("content", delta.content)
```

## 5. Security & Error Normalization

1. **Authentication Failures (HTTP 401 / 403):** Normalized into `LLMAuthenticationError`. **Immediate abort without retry loops** to prevent account locks or wasted compute.
2. **Rate Limits (HTTP 429):** Normalized into `LLMRateLimitError`. Retries up to 2 times with exponential backoff ($2^{\text{attempt}}$ seconds).
3. **Timeouts:** Normalized into `LLMTimeoutError`. Requests exceeding 120s are safely cancelled.
4. **Secret Sanitization:** All logs pass through `sanitize_log_message()`, which matches and redacts Bearer tokens and `nvapi-*` patterns.
